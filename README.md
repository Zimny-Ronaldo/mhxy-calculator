## 1. 这是什么

单文件 HTML 工具箱，给《梦幻西游》电脑版玩家算养成成本。四个工具（**页签顺序 = `Tools.register` 调用顺序**）：

| 工具 | id | 算什么 |
|---|---|---|
| 人物修炼 | `xiulian` | 攻法/防抗法/猎术的修炼花费，含降修沉没损失 |
| 师门技能 | `skill` | 技能从 X 级点到 Y 级要多少经验 / 金钱 |
| 乾元丹 | `qianyuan` | 奇经八脉乾元丹的经验 / 金钱消耗 |
| 生活技能 | `lifeskill` | 帮派书院学生活技能要多少经验 / 金钱 / 帮贡（含「需要持有」门槛） |

**核心约束**：单文件、零依赖、无外链（双击即用、断网可用，不引 CDN / 字体 / 框架）；
不要页脚 / 页面内说明卡片 / 可见自检面板（校验放测试 + 静默 `console`）；中文界面。

## 3. 架构：四层 + 工具注册表

依赖严格单向（上层可依赖下层，反之不行）：

```
① 数据岛  <script type="application/json" id="data-skill">
② 引擎块  engine-skill / engine-xiulian / engine-qianyuan / engine-lifeskill
          ↑ 纯函数、零 DOM；测试用正则整块抽出来对拍
③ 主程序  基础设施(fmt/esc/$) → UI 组件库(ui) → 工具注册表(Tools) → 各工具视图
④ 启动    Tools.boot(document.getElementById('host'))
```

```js
Tools.register({
  id:'xxx', name:'工具名', tagline:'一句话', dataId:'data-xxx',   // 没有数据岛就写 null
  create(ctx){          // ctx = { host, data, ui, fmt, esc, $, invalidate }
    host.innerHTML = ui.card({ title:'…', body:'…' });
    return { render(){ /* 按 state 重绘 */ } };
  },
});
```

- **注册顺序 = 页签顺序**；启动默认加载第一个（人物修炼），`location.hash` 也是它
- 懒加载：首次激活才 `create`，之后常驻，切换只改 `hidden` → **各工具输入状态天然保留**
- `invalidate()` 用 rAF 合并，一帧最多渲染一次；工具之间互不可见、不共享状态

## 4. 共享 API

```js
fmt.num(n)    // 1234567 → "1,234,567"
fmt.cn(n)     // 170460000 → "1.7046 亿"；91650000 → "9,165 万"（末尾 0 去掉）
fmt.raf(fn)   // 每帧最多执行一次
esc(s)        // HTML 转义，所有进 innerHTML 的数据字符串都要过

ui.card({title, body, cls})        ui.field({label, id, hint, value, attrs, tag})
ui.stats([{k,v,sub,tone}], {hero}) ui.pills([{text,tone}])
ui.table({head, rows, total, cls}) ui.alert(text) / ui.idle(text)
ui.seg([{id,name}], activeId)      ui.opts([{id,name,tag}], activeId)
```

`ui.table` 行可以是 `['a','b']` 或 `{cells:[…], cls}`，单元格可为 `{text, cls}`。
`tone`：`jade`(经验/绿) `gold`(金钱/金) `red`(损失/红)；`hero:true` 是跨整行的大号数字。

## 5. 四个工具的数据与公式（改动前必读）

### 5.1 师门技能 `skill`

数据岛 `data-skill`：`{ cost:{exp[180], gold[180]}, sects:[…], milestones:{…} }`，第 i 项 = 「升到 i+1 级」的消耗。

**消耗规则**：
- **1–30 级只收金钱、不收经验**（官方接口实测 `0→30` = 经验 0 / 金钱 26,291）。这条**只写在 `SkillEngine` 的 `FREE_EXP_UNTIL`**；
  ⚠️ **数据岛那 30 个经验值没改** —— 生活技能引擎用同一张表，而**帮派书院 1–30 级照收经验**（官方帮派接口实测）
- 31–150 级高度吻合 `(2L⁴ + 60L³)/375 + 16L`，有 ±1 取整差异 → **以逐级表为准**，公式只作交叉校验
- 151 级起是真实台阶跳变：151–155 = 公式值 ×2.00，156–160 = ×3.00，161 起继续分段
- 金钱/经验比：1–160 = **0.375**；161–180 = **0.3**（所以 160→161 会「经验涨、金钱反降」）

**已修正的原表 5 处笔误**（数据岛里已是修正值）：112 级经验 1,065,190→**1,065,790**；117 级 1,256,104→**1,257,536**；
161 级金钱 450,041→**4,510,041**；163 级整行缺失→**15,600,468 / 4,680,138**；179 级 34,492,930→**34,429,930**。
> 副作用：原表 5 个分段合计因含 112/117 笔误比修正后少 2,032 —— 原表内部矛盾，自检按修正值写死。

**验证锚点**：

| 区间 | 经验 | 金钱 |
|---|---|---|
| 0→30 | **0** | 26,287 |
| 0→150 | 102,987,846 | 38,646,689 |
| 150→160 | 94,383,720 | 35,393,892 |
| 0→180 | 660,314,326 | 212,923,391 |
| 160→180 | 462,942,760 | 138,882,810 |
| 174→180 | 200,884,590 | 60,265,374 |
| 7 技能 0→150 | 720,914,922 | 270,526,823 |

> 带 0 起点的锚点都**扣掉了 1–30 级经验（70,140）**，就是官方接口的取值；**页面静默自检仍直接校数据岛**，用的是原表值。

**门派数据**：21 门派 × 7 技能 = **147 个技能 / 288 个法术引用**，抓自官网各门派介绍页。首行 = 主技能；
253/288 条能正则解析出解锁等级；只有**龙卷雨击**有人工核实档位（25/50/75/100/125/150 → 秒 2~7），
其余群法**没有通用公式**（实测除数 10/25/30/40/50 都有），别硬套。

**UI 要点**：单技能 / 组合计算（整个门派）两模式；组合是三栏（左输入 / 中技能 / 右法术）。
- 技能行**不显示「N 个法术」**；属性精简成标签（`速度` / `伤害` / `命中`），正则 `^(?:按(?:技能)?等级提(?:高)?|提高角色的?)(.+)$`，
  末尾的「力」只在超过两个字时去掉（这样 `伤害力/伤害` 能统一、又保住 `灵力`）；与主技能同款不同色；长句说明和「无」一律不显示
- 等级输入框宽 **84px**（否则 `0 ~ 179` 的占位提示被截）；滑条**悬停即预览**会选到几级（`.rval`，不改实际值）
- **不填不算**：初始不预填，`from` / `to` 用 `null` 表示未填；组合只统计「勾选且填完」的；夹紧只在两项都填完后做
- 滑条未填时停在最左（`0` / `1`）；这两个端点值靠预设 chip 或直接输入设置 —— 不是 bug
- `defFrom` / `defTo` 记住**用户上次点过「应用」**的值，换门派时新行沿用（是回放用户输入，不是默认值）

### 5.2 人物修炼 `xiulian`

引擎参数化，三种类型只差「单价 / 上限 / 是否可降修」：

```js
TYPES = [
  { id:'atk',  perClick:30000, capMax:25, canLower:true  },  // 攻修/法修
  { id:'def',  perClick:20000, capMax:25, canLower:true  },  // 防御/抗法
  { id:'hunt', perClick:30000, capMax:20, canLower:false },  // 猎术
]
BASE_CAP = 20
```

```
E(N) = (N² + 3N + 11) × 10        升到 N 级所需经验
点击次数 = E(N)/10（每点 1 次得 10 经验，耗 5 帮派资材）
帮贡门槛 = 目标等级 × 150（只作门槛，不扣除）      金钱 = 经验/10 × 单价
飞升后基础上限 20，可逐级降修到 25；猎术硬锁 20 且不可降修
```

**降修**：每次「等级 −1、上限 +1」**本身免费**，代价是被降掉那级已投入的经验/金钱作废（沉没成本）；触发条件 `上限 − 当前等级 < 2`。

**验证锚点**（零误差）：攻修 0→20 = 11160 万；攻修 20→25 = 9165 万；防修 20→25 = 6110 万；攻修 15→25 = 15030 万；
防修 15→25 = 10020 万；**20级/上限20→25 逐级降修沉没经验 = 26270**（官方原文示例），降修 5 次 / 降修后 22 级 / 净花费 17046 万。

**出处与范围**：`E(N)`、每点 1 次 / 5 资材 / 帮贡门槛 = 等级 × 150 来自官方《人物修炼》页；单价来自官方 2024-12 攻略原文。
- ✅ **猎术 3 万/次**（攻/法/猎 3 万、防/抗法 2 万）与 ✅ **降修免费**都是**用户确认的游戏设定**，
  不要再标"不确定"、也不要再考证（降修那步 `money` 恒为 0 是**照着设定写的**）
- **只算「飞升后的逐级降修」**，不实现飞升一次性降修（那张表不在本仓库）—— 是**功能范围**，不是数据存疑

**UI 口径**（用户反复反馈后定的，别改回去）：
- **切类型保留已输入值**（只重算不清空；只有猎术会把上限框钉回 20），方便直接对比攻 / 防单价
- **当前等级 ≤ 上限是硬约束**：超了就夹到上限并在结果区说明「已按 N 级计算」，绝不默默按另一个数字出结果。
  `trimLvOnEdit()` 管「编辑当前等级」时夹（并清除过时提示），`trimLvAgainstCap()` 管「上限变小 / 换类型」时被动夹（只设提示）
- **只展示花费**，不展示修炼经验 / 点修次数；「降修明细」表**仅在降修次数 > 0 时出现**，沉没损失并进该表
- 明细 chip 含「降修后 X 级」，合计行写「终态 X 级 / 上限 Y」；操作列只留纯文本 `点修` / `降修`
- 降修明细表用 `cls:'tall flow'`：`.table-wrap.flow` 把 `#` 与 `操作` 钉成 `width:1%`，
  否则自动布局 + 合计行的 `colspan` 会把窄列撑开，序号和操作之间留一大片空白
- **`input` 绝不夹紧写回**（见 §8.6）

### 5.4 生活技能 `lifeskill`

**数据出处（唯一口径）**：官方综合工具箱的「帮派技能计算」，接口
`https://xyqtransfer.webapp.163.com/api/get_life_skill_upgrade_need?skill_id=<ID>&from_lv=<a>&to_lv=<b>`（JSONP，要带 `Referer`）。
21 个技能**逐级全量写死**（2660 个等级，逐级对拍零误差）。网上流传的「学满总表」（3DM / 九游那几张图）总值基本对，
但**逐级值抄错、上限也标错**，不要拿它当数据源。

| 规律 | 说明 |
|---|---|
| 经验 | 大多数技能**就是 §5.1 的师门表**；只有三类从某个等级起进入分段倍率 |
| 金钱 | **不随经验放大，只跟等级走**（强身术经验 1.04 亿，金钱仍与冥想 0→140 相同）→ 1-150 通用表 + 151-160 两段尾巴 |
| 帮贡 | 学第 L 级**消耗 L 点** → 跨 `[a,b]` 消耗 `Σ(a+1..b)`；**需要持有 = 目标等级 × 5**（门槛，不扣除） |

**五类曲线**：常规（冥想 · 暗器 · 中药医理 · 追捕 · 逃离 · 养生 · 健身 · 巧匠 · 熔炼 · 烹饪）= 全程师门表；
强身术 = 1-120 师门表 + 121-140 单列；打造 · 裁缝 · 炼金 · 淬灵 = 1-150 师门表 + 151-160 另一条更低曲线；
灵石技巧 = 1-80 师门表**后移 15 级**（= 师门 16-95）+ 81-120 单列；
强壮 · 神速 · 风/雨/雪之感应 = `20000L² + 200000L + 1500000`（41 级起额外 `+8000000×(L−40)`），金钱恒为经验 1/4。

**上限**：140 = 强身术 · 烹饪技巧；160 = 冥想 · 暗器 · 打造 · 裁缝 · 中药医理 · 炼金 · 追捕 · 逃离 · 养生 · 健身 · 巧匠 · 熔炼 · 淬灵；
120 = 灵石技巧；60 = 强壮 · 神速；20 = 风 · 雨 · 雪之感应。

**UI 口径**：初始不预填、不计算（下拉默认第一项「强身术」）；
结果区四张卡 = **消耗金钱 / 消耗经验 / 消耗帮贡 / 需要持有帮贡**（后两项就是官方计算器的「消耗帮贡」「需要帮贡」）；
每个技能标理论上限，**超了就按上限算并在结果区说明**（说明保留到下次编辑 —— 因为 `change` 已把输入框夹回去了）；
切技能保留已输入等级；明细**每 5 级一档**；**没有「学费指数」输入**（官方 2014-10-13 公告已取消该设定，一律按 5 算）。

## 6. 怎么加第 5 个工具

1. 数据大就加数据岛 `<script type="application/json" id="data-xxx">{…}</script>`；小配置直接写在工具里
2. 写引擎块，插在 `<script id="engine-lifeskill">` 之后、主 `<script>` 之前（纯函数，**禁止 document / window**）
3. 在 `Tools.register` 里注册（模板注释就在注册表上方）。**注册顺序 = 页签顺序**
4. 加测试：`engine.test.mjs` 加引擎抽取 + **外部可核对的锚点数字**；`ui.test.mjs` 加交互断言（**记得改页签数量断言**）
5. 跑 §11 的四套测试

## 7. 测试基础设施

`tests/dom.mjs` 是**手写的零依赖迷你 DOM**（没引 jsdom）：支持常用选择器、`classList` / `dataset`、`<select>` 取值语义、
**带冒泡的事件**（工具全靠事件委托）、`getBoundingClientRect()`（无布局引擎，返回默认矩形，可用 `el._rect` 覆盖）、
`innerHTML` / `textContent` / `closest`；`requestAnimationFrame` / `setTimeout` 同步执行便于断言；
`document.getElementById` 对数据岛直接返回原始文本。

| 文件 | 抽哪块 | 测什么 |
|---|---|---|
| `engine.test.mjs` | `<script id="engine-*">` | 纯公式与数据表，对着**外部公开数字**断言 |
| `ui.test.mjs` | 全部 script 块 | 外壳启动、页签、各工具的初始化与交互、结果渲染 |

`ui.test.mjs` 读**精确数字**（`.stat .sub` / `fmt.num` 输出），不读格式化后的「1.70 亿」；
结果卡**按标签取**（`statOf('消耗经验')`）而不是按下标，免得调整顺序就误报。

## 8. 已知的坑（踩过的，别再踩）

- **8.1 内联 script 的文本陷阱**：代码里出现字面 `</script>`（**包括写在注释里的**）要写成 `<\/script>`；
  块注释里出现 `*/` 会提前闭合注释（文档模板这类内容一律用 `//` 行注释）。
  症状是**整块代码消失**，`new Function` 抛 `Invalid or unexpected token` 或 `Unexpected token '}'`
- **8.2 正则抽取会命中注释里的假 id**：模板注释里写了 `engine-xxx` / `data-xxx`，`grep` 会多出来 —— **不是 bug**，别去"修"
- **8.3 迷你 DOM 不完整**：改测试时遇到"浏览器里明明可以"，先怀疑它缺特性（`<select>` 语义、事件冒泡都是后来补的）。补它是正确做法，别绕过
- **8.4 改数据要连带跑测试**：数据岛是内联 JSON，改完**必须跑 `engine.test.mjs`**；页面末尾 `selfCheck()`
  （师门 12 项 + 生活 21 项）只在出错时 `console.error`，不占界面
- **8.5 性能**：结果区**骨架常驻、只改文本**；重内容（180 级明细）**收起时完全不构建**，展开才建（110ms 防抖）；
  滑条 `input` 要 rAF 合并且**只在值真变了才回写 DOM**；`body` 的装饰渐变放独立固定图层 `body::before`
- **8.6 别在 `input` 里夹紧写回输入框**：下限 > 0 时必然出事 —— 修炼上限合法区间 20~25，逐字输入「20」：敲 `2` 被夹成 `20`、
  再敲 `0` 变成 `200` 又被夹成 `25`，用户永远填不进 20。
  **正确做法**：`input` 只重算，写回拆到 `change` / `blur`（`applyMeta()` 每次渲染都跑、`commitInputs()` 只在 `change`/`blur` 跑）。
  **测这类 bug 必须逐字追加模拟**（`typeInto()`），直接 `node.value='20'` 会绕过脏值，测试永远绿
