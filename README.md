## 1. 这是什么

一个**单文件 HTML 计算工具箱**，给《梦幻西游》电脑版玩家算养成成本。目前三个工具：

页签顺序 = 工具注册顺序（`Tools.register` 的调用顺序），**第一页是人物修炼**：

| 工具 | id | 算什么 |
|---|---|---|
| 人物修炼 | `xiulian` | 攻法/防抗法/猎术的修炼花费，含降修沉没损失 |
| 师门技能 | `skill` | 技能从 X 级点到 Y 级要多少经验 / 金钱 |
| 乾元丹 | `qianyuan` | 奇经八脉乾元丹的经验 / 金钱消耗 |

**核心约束（用户明确要求，别破坏）：**
- **单文件、零依赖、无外链** —— 双击浏览器打开即用，断网可用，不引 CDN/字体/框架
- **不要页脚、不要页面内说明卡片、不要内置自检面板** —— 数据校验放测试代码 + 静默 `console`
- 中文界面，视觉统一在下面这套设计系统里

## 3. 架构：四层 + 工具注册表

文件内部按下面顺序组织，**依赖严格单向**（上层可以依赖下层，下层不许反向依赖）：

```
① 数据岛   <script type="application/json" id="data-skill">     ← 大数据与代码分离
② 引擎块   <script id="engine-skill">    function SkillEngine(data){…}
           <script id="engine-xiulian">  const XiulianEngine = (…)()
           <script id="engine-qianyuan"> const QianyuanEngine = (…)()
           ↑ 纯函数、零 DOM，可被测试代码整体抽出来对拍
③ 主程序   基础设施(fmt/esc/$) → UI 组件库(ui) → 工具注册表(Tools) → 各工具视图
④ 启动     Tools.boot(document.getElementById('host'))
```

### 为什么引擎要单独成块

两个原因，缺一不可：

1. **可测试**：`tests/engine.test.mjs` 用正则把 `<script id="engine-xxx">` 整块抽出来，`new Function` 执行后直接断言纯函数。如果引擎写在工具闭包里就抽不出来。
2. **架构约束**：引擎块里**不允许出现 DOM 访问**，这是硬边界。

```js
// tests/engine.test.mjs 的抽取方式
const block = id => html.match(new RegExp(`<script id="${id}">([\\s\\S]*?)</script>`))[1];
const { QianyuanEngine } = new Function(`${block('engine-qianyuan')}\nreturn { QianyuanEngine };`)();
```

### 工具契约

```js
Tools.register({
  id: 'xxx',                 // 唯一 id，同时是 URL hash
  name: '工具名',             // 页签文字
  tagline: '一句话说明',
  dataId: 'data-xxx',        // 没有数据岛就写 null
  create(ctx){
    // ctx = { host, data, ui, fmt, esc, $, invalidate }
    //   host        本工具根节点（<div class="tool tool-xxx">），直接写 innerHTML
    //   data        数据岛解析结果；dataId 为 null 时是 null
    //   ui          统一组件库（见 §4）
    //   fmt         num / cn / raf（见 §4）
    //   esc         转义函数，所有进 innerHTML 的数据字符串都要过
    //   $           (sel, root=document) => root.querySelector(sel)
    //   invalidate  节流到下一帧重绘本工具
    host.innerHTML = ui.card({ title:'…', body:'…' });
    // 建骨架、绑事件（事件委托一律绑在 host 上，用 e.target.closest）
    return { render(){ /* 把当前 state 画出来 */ } };
  },
});
```

**运行时行为**（`Tools` 内部）：
- **页签顺序 = `register` 调用顺序**：当前为 人物修炼 → 师门技能 → 乾元丹；启动默认加载第一个（人物修炼），`location.hash` 也是它
- 工具**懒加载**：首次激活才 `create`，之后常驻，切换只改 `hidden`
- 所以**各工具的输入状态天然保留**，切走再切回不丢
- `invalidate()` 用 `requestAnimationFrame` 合并，一帧最多渲染一次
- 工具之间**互不可见、不共享状态**；共享的只有 `ui` / `fmt` / `esc` 三个纯工具

## 4. 共享 API

```js
fmt.num(n)    // 1234567 → "1,234,567"
fmt.cn(n)     // 亿（最多 4 位小数）/ 万（最多 2 位）+ 千分位，末尾 0 去掉
              //   170460000 → "1.7046 亿"   91650000 → "9,165 万"
fmt.raf(fn)   // 返回一个「一帧最多执行一次」的包装函数
esc(s)        // HTML 转义，防止数据里的 < > & " 破坏结构

ui.card({title, body, cls})       ui.field({label, id, hint, value, attrs, tag})
ui.stats([{k,v,sub,tone}], {hero}) ui.pills([{text,tone}])
ui.table({head, rows, total, cls}) ui.alert(text)
ui.idle(text)                      ui.seg([{id,name}], activeId)
ui.opts([{id,name,tag}], activeId)
```

**`ui.table` 的行格式**：行可以是裸数组 `['a','b']`，也可以是 `{ cells:[…], cls:'lower' }`；单元格可以是字符串，也可以是 `{ text, cls }`。`total` 是单元格数组。

**`stat` 的 tone**：`jade`（经验/绿）、`gold`（金钱/金）、`red`（损失/红）；`hero:true` 是跨整行的大号数字。

## 5. 三个工具的数据与公式（改动前必读）

> 下面小节的先后按「资料整理顺序」排，**不代表页签顺序**（页签顺序见 §1 / §3）。

### 5.1 师门技能 `skill`

**数据岛 `data-skill`** 结构：
```js
{
  cost: { exp: [180个数], gold: [180个数] },   // 第 i 项 = 「升到 i+1 级」这一级的消耗
  sects: [{ name, abbr, spells: { 法术名: { t:描述, u:[技能名,等级] } },
            skills: [{ name, main, effect, desc, spells:[法术名] }] }],
  milestones: { 龙卷雨击: [[25,'秒 2'], …] }
}
```

**消耗规则（不是一条公式，是分段 + 查表）**：
- **1–150 级**高度吻合四次曲线 `(2L⁴ + 60L³)/375 + 16L`，但存在 ±1 取整差异 → **以逐级表为准**，公式只作交叉校验
- **151 级起是真实台阶跳变**：151–155 恰为公式值的 **2.00 倍**，156–160 恰为 **3.00 倍**，161 起继续分段跳
- **金钱/经验比**：1–160 级 = **0.375**；161–180 级 = **0.3**（所以 160→161 会出现"经验涨、金钱反降"）

**已修正的原表 5 处笔误**（数据岛里已是修正值）：

| 位置 | 原表 | 修正为 | 依据 |
|---|---|---|---|
| 112 级经验 | 1,065,190 | 1,065,790 | 该级金钱 399,671 与平滑曲线同时指向 |
| 117 级经验 | 1,256,104 | 1,257,536 | 同上（金钱 471,576） |
| 161 级金钱 | 450,041 | 4,510,041 | 漏一位；其余各级比值均为 0.3 |
| 163 级 | 整行缺失 | 15,600,468 / 4,680,138 | 原表这行等级被误标成 162 |
| 179 级经验 | 34,492,930 | 34,429,930 | 该级金钱列与 161–180 分段合计同时锁定 |

> 副作用：原表 5 个分段合计（1-120/1-130/1-150/91-120/101-125）因含 112/117 笔误，比修正后少 2,032。**这是原表内部矛盾，不是算错**，自检里已按修正值写死。

**验证锚点**（测试与静默自检都用这些）：

| 区间 | 经验 | 金钱 |
|---|---|---|
| 0→150 | 103,057,986 | 38,646,689 |
| 150→160 | 94,383,720 | 35,393,892 |
| 0→180 | 660,384,466 | 212,923,391 |
| 160→180 | 462,942,760 | 138,882,810 |
| 174→180 | 200,884,590 | 60,265,374 |
| 7 技能 0→150 | 721,405,902 | 270,526,823 |

**门派数据**：21 门派 × 7 技能 = **147 个技能 / 288 个法术引用**，全部从 `xyq.163.com` 各门派介绍页（`mp001.html`~`mp015.html` + 新门派独立页）抓取解析。
- 每门派技能表首行 = **主技能**
- 法术解锁等级从描述里正则解析「XX技能达到N级」，**253/288 条**能解析出来
- 只有**龙卷雨击**有人工核实的等级里程碑（25/50/75/100/125/150 → 秒 2~7），其余群法档位**没有通用公式**（实测除数因法术而异：10/25/30/40/50 都有），别硬套

**UI 要点**：单技能 / 组合计算两模式（`batch` 是内部 id，界面上叫「组合计算（整个门派）」）。组合模式是**三栏**（左输入 / 中技能 / 右法术），点技能名切换右栏。明细按**每 5 级一档**（`bandsOf`），正好让 150→160 切成 151-155 / 156-160 两档，对上真实跳变。

**技能栏展示口径**：
- 行内**不再显示「N 个法术」**（法术列表在右栏）
- 行内把技能属性**精简成标签**，用和「主技能」同一套 `.tag` 样式、只换颜色（`.tag.attr`，金色→青色）：
  `按技能等级提高躲避力` → `躲避`、`按技能等级提伤害力`（数据里就有的错字写法）→ `伤害`、`提高角色的速度` → `速度`、`按等级提高法伤和法防` → `法伤` + `法防`
- 精简规则 `attrTags()`：正则 `^(?:按(?:技能)?等级提(?:高)?|提高角色的?)(.+)$` 覆盖数据里全部 4 种前缀，再按 `和 、 ,` 拆多个标签；
  末尾的「力」**只在超过两个字时去掉**，这样 `伤害力/伤害`、`防御力/防御`、`躲避力/躲避` 能统一，同时保住 `灵力`
- **长句说明与「无」一律不显示**（花果山 / 天机城 / 九黎城主技能、弥勒山那条"其他门派技能…"），不硬凑标签；完整说明仍在右栏「法术详情」里
- 等级输入框宽度 **84px**（原 58px / 64px），否则初始态空框里的 `0 ~ 179` 占位提示会被截掉看不全
- 单技能的两个滑条**鼠标悬停即预览「这个位置会选到几级」**（`.rval`，不用点击、**不改动实际值**）：
  把光标 x 映射到 `[min,max]` 并按 step 吸附；气泡位置按预览值对应的滑块中心算 `left = pct% ± (9 − 18×pct)px`；拖动时同步、移开收起

**「不填不算」口径（与人物修炼统一）**：
- 初始**不预填任何等级**，结果区只显示「填写当前等级与目标等级后自动计算」；`state.single` / 每个 row 的 `from`、`to` 用 **`null` 表示还没填**，`ready()` 判定两项都拿到数字才算
- 单技能：两项都填完才出结果；只填一项时保持待填写；`#sk-detail`（消耗明细）在无结果时整个隐藏
- 组合计算：只把**「勾选 且 等级填完」**的技能计入合计；一个都没有时显示待填写。统一设置（`#sk-def-from` / `#sk-def-to`）没填完时「应用」是空操作
- 夹紧只在两项都填完后做（`normalize`），所以不会把空值当成 0
- 滑条未填写时**停在最左**（`0` / `1`）；因为停在端点再拖到端点不产生 `input` 事件，这两个端点值走**预设 chip**（`0` / `180`）或直接输入数字来设置——不是 bug，别去"修"
- `defFrom` / `defTo` 记住**用户上次点过「应用」**的值，换门派时新行沿用它（这不是默认值，是用户输入的回放）

### 5.2 人物修炼 `xiulian`

**引擎是参数化的**：三种类型只差「单价 / 上限 / 是否可降修」三个参数。

```js
TYPES = [
  { id:'atk',  perClick:30000, capMax:25, canLower:true  },  // 攻修/法修
  { id:'def',  perClick:20000, capMax:25, canLower:true  },  // 防御/抗法
  { id:'hunt', perClick:30000, capMax:20, canLower:false },  // 猎术
]
BASE_CAP = 20
```

**公式**：
```
升到 N 级所需经验  E(N) = (N² + 3N + 11) × 10
点击次数          E(N) / 10            （每点 1 次得 10 经验，耗 5 帮派资材）
帮贡门槛          目标等级 × 150        （只作门槛，不扣除）
金钱              经验 / 10 × 单价
飞升后基础上限     20；可逐级降修到 25；猎术硬锁 20 且不可降修
```

**降修规则**：每次「等级 −1、上限 +1」，**本身免费**；代价是被降掉那一级已投入的经验/金钱**作废**（沉没成本）。触发条件：`上限 − 当前等级 < 2`。

**验证锚点**（全部零误差）：

| # | 场景 | 期望 |
|---|---|---|
| A | 攻修 0→20 累计 | 11160 万 |
| B | 攻修 20→25 纯点修 | 9165 万 |
| C | 防修 20→25 纯点修 | 6110 万 |
| D | 攻修 15→25 纯点修 | 15030 万 |
| E | 防修 15→25 纯点修 | 10020 万 |
| F | 20级/上限20→25 逐级降修**沉没经验** | **26270**（官方原文示例） |
| — | F 场景降修次数 / 降修后等级 / 净花费 | 5 次 / 22 级 / 17046 万 |

**数据出处与适用范围**：
- 经验公式 `E(N)`、「每点 1 次得 10 经验 / 5 帮派资材 / 帮贡门槛 = 等级 × 150」来自官方《人物修炼》页
- 单价依据官方 2024-12 攻略原文："攻击修炼、法术修炼每次花费 3 万，防御修炼、抗法修炼每次花费 2 万"
- ✅ **猎术 3 万/次 —— 已由用户确认为游戏设定**（攻/法/猎 3 万、防/抗法 2 万）。
  官方费用表那一页是 GBK 乱码，最初只能靠"5 行费用 30000/20000/30000/20000/30000 对应 攻/防/法/抗法/猎"间接解读，
  现已拍板，**不要再写成"不确定"**，也不要再去重新考证
- ✅ **降修免费 —— 已由用户确认为游戏设定**：每次「等级 −1、上限 +1」本身不收费，
  代价只有被降掉那一级已投入的经验/金钱作废（沉没成本）。
  引擎里降修那步的 `money` 恒为 0 是**照着设定写的**，不是"暂按免费处理"的待定项
- **本工具只算「飞升之后的逐级降修」**，不实现"飞升一次性降修"（飞升瞬间按表把修炼等级降掉、
  上限直接给到 20~25，如 20→15/上限 25、19→15/上限 24 …、≤12 不降）。
  这是**功能范围**（那张飞升降修表不在本仓库里），不是数据存疑；要补这个场景先按开头的协作约定问用户

**UI 口径（用户反复反馈后定的，别改回去）**：
- 初始**不计算**，显示"填写左侧三项数据后自动计算"；三项没填完一律不算 —— 这条后来推广成了**三个工具的统一口径**（见 §5.1 / §5.3）
- **切换修炼类型保留已输入的修炼值**（只重算、不清空；只有猎术会把上限框钉回 20）。曾按"切类型清空"做过，用户反馈要保留，所以同一组等级能直接对比攻/防单价
- **当前修炼等级 ≤ 当前修炼上限是硬约束**：输入超过上限时**就地夹到上限**，并在结果区明确说明「当前修炼等级不能超过当前修炼上限（N 级），已按 N 级计算」——绝不默默按另一个数字出结果。
  实现上分两条路：`trimLvOnEdit()` 在用户编辑当前等级时夹（并负责清除过时提示），`trimLvAgainstCap()` 在上限改小 / 换类型时被动夹（只设提示不清提示，避免 `change`+`blur` 二次触发把提示抹掉）
- **只展示花费**，不展示修炼经验 / 点修次数
- 「降修明细」表**仅在降修次数 > 0 时出现**，沉没损失并进这张表
- 明细 chip 含「降修后 X 级」，合计行写「终态 X 级 / 上限 Y」
- 操作列只保留纯文本 `点修` / `降修`，不加任何标签
- 降修明细表用 `cls: 'tall flow'`：`.table-wrap.flow` 把 `#` 和 `操作` 两列钉成 `width:1%` 收缩宽度，否则表格自动布局 + 合计行的 `colspan` 会把窄的 `#` 列一起撑开，序号和操作之间留出一大片空白
- 不加"需要先降修，详情见下表"这类整句（会挡在表格前面）
- **输入过程中绝不夹紧写回**：`input` 只触发重算（`render` 里的 `applyMeta` 只刷范围提示 / 占位 / 禁用态），夹紧写回放在 `change` / `blur` 的 `commitInputs()` 里。
  原因是上限框的**下限是 20**，若在 `input` 里写回，逐字输入「20」时敲下 `2` 就被夹成 `20`，再敲 `0` 变成 `200` 又被夹成 `25` —— 用户永远填不进 20（已加回归测试，见 §8.6）

### 5.3 乾元丹 `qianyuan`

**数据来源是两套独立资料互相印证**（这段经历值得记住，网上关于乾元丹的 AI 垃圾文极多）：

1. **叶子猪「乾元丹经验计算器」**（`xyq.yzz.cn/special/qyd/js/calculate.js`）：完整的**旧版 60 个逐丹数据表**

- 引擎里的 `maxAffordable`（经验反查）**保留并有测试覆盖**，只是 UI 不再调用——以后想加回来不用重写算法

## 8. 已知的坑（踩过的，别再踩）

### 8.1 内联 `<script>` 里的文本陷阱

**这两类字符会截断代码，且不会报"语法错误"，而是让整块代码消失：**

- 代码里出现字面 `</script>` —— 包括**写在注释里的**。要写成 `<\/script>`
- 块注释 `/* … */` 里出现 `*/` —— 会提前闭合注释。**文档模板这类内容一律用 `//` 行注释写**

我在同一个文档注释上两个都踩过一次，症状是 `new Function` 抛 `Invalid or unexpected token` 或 `Unexpected token '}'`。

### 8.2 正则抽取会命中注释里的假 id

注册表上方的模板注释里写了示例 `<script id="engine-xxx">`，所以 `grep '<script id="engine-'` 会多出 `engine-xxx`；数据岛同理多出 `data-xxx`。**不是 bug**，别去"修"。

### 8.3 迷你 DOM 不完整

它是为这个项目手写的，不是完整实现。改测试时如果遇到"浏览器里明明可以"，先怀疑是迷你 DOM 缺特性（比如 `<select>` 语义、事件冒泡就是后来补的）。补它是正确做法，别绕过。

### 8.4 改数据要连带跑测试

数据岛是内联 JSON，改完**必须跑 `engine.test.mjs`**，里面的锚点数字就是防止静默改坏的。文件末尾还有一段 `selfCheck()`（师门技能 12 项），只在出错时 `console.error`，不占界面。

### 8.5 性能相关（改 UI 时留意）

- 结果区**骨架常驻、只改文本**，不要退回"每次 `innerHTML` 整块重建"
- 重内容（师门技能的 180 级明细表）**收起时完全不构建**，只在 `<details>` 展开时建，并用 110ms 防抖
- 滑条 `input` 必须 rAF 合并，且**只在值真的变了才回写 DOM**（回写正在拖的控件会卡）
- `body` 的装饰渐变放在独立固定图层 `body::before`，避免内容重绘时连带重画

### 8.6 别在 `input` 事件里夹紧写回输入框

**症状**：用户填「20」，输入框自己变成「25」。

**原因**：范围夹紧（clamp）写在每次 `render` 里，而 `input` 每敲一个键就触发一次 `render`。
当**下限 > 0** 时必然出事——修炼上限的合法区间是 20~25，逐字输入「20」的实际过程是：

| 按键 | 框里变成 | clamp 后写回 |
|---|---|---|
| `2` | `2` | `clamp(2,20,25)=20` → 覆盖成 `20`，光标跳到末尾 |
| `0` | `200`（追加在脏值上） | `clamp(200,20,25)=25` → 覆盖成 `25` |

**正确做法**：`input` 只重算（`read()` 内部照样 clamp 用于计算），把写回 DOM 拆到 `change` / `blur` 里
（人物修炼：`applyMeta()` 每次渲染都跑、`commitInputs()` 只在 `change`/`blur` 跑）。

**测这类 bug 必须逐字模拟**，不能直接 `node.value = '20'`——要像浏览器那样把字符**追加到当前 DOM 值**后面
（`tests/ui.test.mjs` 里的 `typeInto()`），否则初始的脏值被绕过去，测试永远绿。

> 师门技能的等级框下限是 `0` / `1`，从左往右敲不会踩到下限，所以只有下限为 20 的修炼上限会中招。
